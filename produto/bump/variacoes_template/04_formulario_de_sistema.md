# Variação de template — formulário de sistema

**Quando usar:** a escola usa sistema de gestão (diário eletrônico) e o planejamento é digitado campo a campo numa tela, sem upload de arquivo.

## A técnica: o sistema vira template como qualquer outro

1. Abra a tela de lançamento do sistema e tire um print de um formulário vazio.
2. Rode o template reverso: suba o print e peça a descrição de volta — campos, ordem, limites, listas suspensas.
3. Corrija e salve como `04_TEMPLATE.md`. Inclua o que o print não mostra: limite de caracteres por campo, campos obrigatórios, o que a coordenação espera em cada um.

## Descrição-modelo para o seu `04_TEMPLATE.md`

```
Documento: lançamento por aula no sistema [NOME], via formulário.
Campos, na ordem da tela:
1. Data (seletor)
2. Turma (lista do sistema)
3. Conteúdo/tema (texto, limite ~[N] caracteres)
4. Objetivo/habilidade (texto, limite ~[N] caracteres)
5. Metodologia/desenvolvimento (texto, limite ~[N] caracteres)
6. Recursos (texto curto ou lista)
7. Avaliação (texto curto ou lista)
Regras: respeitar limites de caracteres SEM cortar no meio; texto
direto, sem markdown, sem listas com hífen se o campo não aceitar
quebra de linha.
```

## Prompt de geração

> Gere o lançamento das aulas [X a Y] no formato do 04_TEMPLATE (formulário de sistema): um bloco por aula, com os campos na ordem da tela e cada campo dentro do limite de caracteres. Vou copiar e colar campo a campo.

## Dica de fluxo

Peça os blocos na ordem das aulas e cole na sequência — a digitação de um bimestre inteiro cai para uma sessão. O planejamento-fonte continua sendo a planilha ou a tabela; o formulário é só mais uma renderização.
